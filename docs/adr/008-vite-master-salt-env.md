# ADR-008: Argon2id マスター鍵導出ソルトをビルド時環境変数で注入する

**ステータス:** Accepted
**決定日:** 2026-03-11
**関連:** `docs/progress/08-web-implementation.md`, ADR-003, `crates/cli/src/key.rs`

---

## Context

Argon2id は同じパスワードから常に同じ masterKey を導出するために、**固定のソルト**が必要。
CLI では `solidrop init` 実行時にランダムな 16 バイトのソルトを生成し、`~/.config/solidrop/master.salt` に保存する。
以降の全コマンドがこのファイルを読み込み、Argon2id に渡す。

Web フロントエンドも CLI と同じ masterKey を導出するには、同じソルトが必要。
これを Web アプリにどのように届けるかが未決定だった（`docs/progress/07-web-design.md` の TBD）。

検討した選択肢:

**案A: ビルド時環境変数（VITE_MASTER_SALT_HEX）**
`solidrop init` が出力した salt の hex 文字列を Vite ビルド時に環境変数として渡し、JS バンドルに埋め込む。

**案B: API エンドポイント経由で動的取得**
認証不要の `GET /api/v1/auth/salt` エンドポイントをサーバーに追加し、ログイン時に salt を取得する。

**案C: ユーザーが手動入力**
パスワードに加えてソルトの hex 文字列もログイン画面で入力させる。

---

## Decision

**Phase 1 では案A（VITE_MASTER_SALT_HEX）を採用する。**

```
# ビルド時に設定する（Dockerfileの ARG か .env.local）
VITE_MASTER_SALT_HEX=<solidrop init が出力した 32 文字 hex>
```

このソルトは JS バンドルに埋め込まれ、ログイン時に `@noble/hashes/argon2` に渡される。

---

## Rationale

**なぜソルトはシークレットではないか:**

Argon2id のセキュリティモデルでは、ソルトの役割はレインボーテーブル攻撃の防止と、同じパスワードを持つ複数ユーザー間のキー分離。シークレット（パスフレーズ）は常にパスワードであり、ソルトが漏洩しても masterKey の導出にはパスワードが必要。

CLI も `master.salt` ファイルを秘密保護なしで保存（バックアップに含める前提）しており、ソルト自体を秘密情報として扱っていない。

**なぜ案A（ビルド時注入）か:**

| 観点 | 案A（ビルド時注入） | 案B（API 動的取得） | 案C（手動入力） |
|---|---|---|---|
| 実装コスト | Vite 変数のみ（追加コードなし） | API 変更 + サーバー設定追加 | ログイン UI の変更 |
| UX | パスワード 1 入力のみ | パスワード 1 入力のみ | パスワード + ソルト 2 入力 |
| セキュリティ | バンドルにソルト埋め込み（許容） | サーバーが salt を保持（許容） | ユーザー操作ミスのリスク |
| パスワード変更時 | 再ビルド・再デプロイが必要 | サーバー設定のみ変更 | 特に変更不要 |

Phase 1 のシングルユーザー個人ツールとして、API 変更コストをかけない案A が最も実用的。

**なぜ案C（手動入力）を選ばないか:**

ソルトは 32 文字の hex 文字列。これをログイン時に毎回入力させるのは UX 上許容できない。また、入力ミス時のエラーメッセージ設計が複雑になる。

---

## Consequences

**正の結果:**
- API サーバーに変更不要（Phase 1 で新エンドポイント追加なし）
- ログイン画面はパスワード 1 入力で完結（UX シンプル）
- ソルトがバンドルに埋め込まれるため、オフラインでも動作可能

**負の結果:**
- パスワードを変更（`solidrop init` 再実行）した場合、`VITE_MASTER_SALT_HEX` を更新して Web アプリを再ビルド・再デプロイする必要がある
- 複数デバイスで同じ salt を共有する場合、デバイス間での salt 配布が必要
- `VITE_MASTER_SALT_HEX` がビルド成果物（`dist/assets/index-*.js`）に埋め込まれる。ソルトはシークレットではないが、不用意にリポジトリへコミットしないこと（`.env.local` を `.gitignore` に含める）

**将来の改善案（Phase 2 以降）:**

`GET /api/v1/salt` エンドポイントをサーバーに追加し、ログイン時に動的取得する。
これにより再ビルド不要でパスワード変更に対応できる（DEF-x）。
